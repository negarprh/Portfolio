## Non-negotiable behavior

Projects use named CSS grid areas. Desktop pairs heading/description/stack/actions on the left with screenshot/evidence on the right. Phones follow title → screenshot/evidence → complete description → one quieter stack line → actions. Keep DOM order aligned with this phone sequence. Both actions use plain underlined text. Preserve “Visit live site” and “View on GitHub,” accessible names, new tabs, `noopener noreferrer`, and visible keyboard focus. Actions sit after the description/stack, with 44px desktop and 52px unscaled phone minimum heights; the larger phone target compensates for measured fitting at 320×568. Keep technology labels available to screen readers without a visible TECH heading. Preserve original project paragraphs and the sample-data caption; do not crop images or replace copy with summaries. Measured fitting remains the fallback on smaller screens.

Fixed chapter running labels hide throughout a page turn and return only on the settled reading page. They remain hidden on chapter dividers so an outgoing chapter label never overlays the next chapter.

Phone project titles are centered. All project actions are plain underlined chapter-ink text links, without boxes, logos, or background fills. Paired phone links have equal-width tap areas; a single GitHub action spans the row. Retain 52px unscaled phone targets, centered labels, stronger hover underlines, and a chapter-ink keyboard focus outline. Desktop links use the same unboxed editorial treatment.

- Complete content renders server-side in static document order. With JavaScript disabled, every chapter and the back cover remain readable, native links work, and the `<details>` index functions.
- Fully support `prefers-reduced-motion`, including preference changes while open. Static final states must be immediately readable; navigation and normal scrolling remain available.
- Enhanced vertical wheel/trackpad input uses 75% of its supplied distance and a full-turn speed limit of 850ms, with at most one turn of pending travel. Reversal discards pending movement in the old direction. Keyboard, pinch zoom, horizontal input, and reduced-motion/no-JS scrolling remain native. Upward movement reverses the same physical leaf.
- Do not add WebGL, canvas physics, a 3D engine, cursor tracking, or pointermove/mousemove visual effects. Controlled phone swipes and slowed vertical wheel/trackpad input are the explicit native-scrolling exceptions requested by Negar on 2026-10-16 and 2026-10-19.
- Enhanced phones use a finger-driven, single-leaf gesture instead of native inertia or CSS snap. A full drag requires 0.95 viewport heights of finger travel; displayed drag movement has an 850ms full-turn speed limit even when touch events arrive in large jumps. Releasing a deliberate swipe completes the remaining turn in 300–850ms using smooth acceleration/deceleration; a short swipe returns to the nearest starting page. A new finger immediately brakes settling. Vertical touch moves are prevented only for an active book drag; taps, index use, horizontal gestures, and pinch zoom remain available. Fixed phone pages use `touch-action: pan-x pinch-zoom` so the first gesture does not also pan the document/browser chrome. Reduced motion and no-JS retain native document scrolling.
- Except for the explicitly approved cover signature’s `stroke-dashoffset`, animate only `transform`, `opacity`, or `clip-path`. Never animate layout dimensions/coordinates or `box-shadow`.
- No continuous loop except the restrained 10-second gold accent-dot opacity cycle. Cover signature and seal entrances happen once per mount and settle permanently when interrupted.
- No purple, glassmorphism, drop-shadow cards, or generic technology-cube imagery.

## Motion contract

- Cover, interior, and closing turns use one stationary stage and the same scroll geometry. Scroll position maps linearly onto a 180-degree turn over `TURN_TRAVEL = 0.85` small-viewport heights. Keyboard/programmatic input keeps `TURN_RESPONSE_MS = 32`; larger touch surfaces retain the existing visual speed cap. Phone/wheel controllers pace synchronized positions; index navigation uses a direct current/destination paper effect and synchronizes native scroll on arrival or interruption. Direct hashes, inline links, and browser history land immediately.
- Visible fixed paper and the articulated sheet fill `100dvh`; scroll runways and turn distance use `100svh` so collapsing browser chrome does not move chapter destinations. Refit content when viewport height changes and retain the current touch visual position while remeasuring.
- The final contact runway is at least the visible viewport height, keeping its destination reachable when the address bar retracts; earlier runway positions stay stable.
- Original reading surfaces occupy one fixed viewport-height paper rectangle. All interior surfaces use identical bounds, including nested spreads whose section borders previously narrowed them. The front cover retains its existing full-width dimensions; its turn uses the same mechanism at that width.
- One right-hand sheet crosses the center spine on desktop. Twelve connected 3D segments bend continuously during the rotation, with outgoing recto and incoming verso content, hidden reverse faces, a moving cast shadow, contact shadow, and restrained face lighting. Adjacent joints share endpoints. No paired outward-opening leaves, crossfades, vertical spread translations, or blank decorative sheets.
- The next spread is rendered beneath the outgoing spread. Its right page is exposed by the sheet lifting; its left page arrives on the reverse of that sheet. At rest, the original semantic content owns reading and links. Decorative snapshots are inert, omit IDs and boundary attributes, and preserve the existing typography/materials. Snapshot preparation is warmed while resting and refreshed if the source reading position changes.
- Phones use the same physical turn at full page width with a left-edge hinge. Reading pages have no nested vertical or horizontal scrolling. Full original paragraphs remain present on every screen; do not substitute summaries, truncate, or hide important copy to fit.
- Fit and vertically center each complete reading block inside symmetric page bounds on measurement, font readiness, and resize. Responsive type, spacing, and image sizes establish the layout; a measured layout scale reduces it only as necessary to fit. Above the normal desktop size, scale reading content proportionately up to 1.8× when height permits. The fit is static during a turn. Folios and running heads stay anchored. Every reading runway occupies one viewport height, including Evenly.
- At widths of 1600px and above, paper width grows beyond the original 1240px cap, using 80vw bounded by 180dvh and 56px minimum side margins. Fore-edges share the resulting inset. Preserve readable line lengths and centered geometry; do not stretch the book across an entire super-ultrawide monitor.
- Empty document runways retain native scroll distance and stable chapter destinations. Index, cover link, and inline chapter links use those destinations; hidden reading surfaces are inert. Clearing enhancement removes the fixed positioning, runways, snapshots, visibility and clipping state, restoring the original static document.
- Divider wrappers retain 175svh desktop / 150svh mobile runways. Their geometry remains independent of the CSS-owned chapter materials and typography; page blocks, INDEX, navigation labels, and complete content remain available during enhancement.
- The one-time cover pen entrance reveals the actual Orbitron heading one line at a time using clip-path, with no font swap. It waits for fonts/window load and runs for 2.48 seconds. No-JS, reduced motion, scroll-away, or tab hiding resolve immediately to resting type; it never replays on scroll.
- The front NP seal also waits for fonts and page assets, enters once, and remains still. Its static fallback stays visible without JavaScript or with reduced motion.

## Accessibility and truthfulness checks

- Preserve skip link, semantic headings, native anchor targets, keyboard index behavior, and honest image alternative text.
- Do not hide content based on animation completion.
- Browser wheel/trackpad tests simulate input. They do not establish physical-device performance or guarantee zero dropped frames.
- After visual changes, inspect both desktop and mobile covers/chapters in addition to automated assertions.
